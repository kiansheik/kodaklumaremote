## What worked

- Focused sync and both brightness regressions passed.
- Guarded release passed 247/247 Node and 163/163 browser tests, built both
  signed APKs, committed/pushed source as `bd9223f`, and published stable
  release `v0.4.12` (not draft/prerelease).
- Phone manifest: 0.4.12/code 22, 9,822,418 bytes, SHA-256
  `3907cd8c4fd0890ce7b7441a378eea04c1dfcd4c391b3f980a9db85269681617`.
- Receiver manifest: 0.3.2/code 16, 1,134,598 bytes, SHA-256
  `b45d3e642c988d8eac256e8813fa1613308e50fd0f7577c4929cde7869ac2fdb`.
- Corrected Pages commit `5decdde` built successfully; the exact speed-dial URL
  and both live manifests returned the expected content.

## What failed

- A sandboxed focused Playwright start could not bind 127.0.0.1:4173; the
  authorized local-server run passed.
- The initial successful Pages commit `258a5af` omitted `tv.html`: the build
  script created it, but the deployment script copied only its older explicit
  list. Live verification caught the resulting 404. The allowlist/test fix and
  page-only redeployment resolved it without another Android release.
- `make push` is not a repository target. `make deploy-gh-pages` owns the source
  commit/push/release workflow; `make deploy-page` republishes an existing
  release's Pages artifacts.
