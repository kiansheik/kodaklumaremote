## Publication and source proof

Published [v0.4.6](https://github.com/kiansheik/kodaklumaremote/releases/tag/v0.4.6)
from commit2c177b21ac4a1a7b5ac94219b1d7d9a88e063768. Both assets are uploaded;
release is public/stable. The install page was deployed, Pages reports built,
and the live HTTPS update feed exactly matches the prepared manifest. A fresh
public APK download matches the recorded SHA/size. No physical app update was
performed during the current Kodak viewing session.

Automatic upload review initially rejected a missing embedded Git revision:
AGP9.3.1 hardcodes Gradle-root/.git, while this repo's Gradle project is nested in
android/. Its honest output is NO_SUPPORTED_VCS_FOUND. No metadata was forged or
disabled. An independent clean checkout of the exact source commit was rebuilt
with the same pinned dependencies and production key. All125ZIP payloads, ZIP
metadata, signature-v2 block and bytes outside the signing block match. The only
difference is hybrid-encrypted SDK dependency block0x504b4453; both underlying
SDK reports/protobufs match exactly. Whole-file hashes therefore differ, and that
fact is retained in the private proof rather than called byte-identical. After
this source verification, automatic review accepted the normal publisher retry.
See docs/releasing.md and private release-clean-source-proof.json/log.

Python's local CA configuration rejected HTTPS verification; system curl verified
both downloads with TLS checks enabled. No insecure TLS bypass was used.

## What worked

Today's earlier Philips episode has user-confirmed smooth picture/sound/PT-BR.
New Library stores all observed title/episode records independently of recent100,
preserves progress through restart/metadata failures and keeps reads offline.
Source-safe observer guards and durable resume lookup are checked. Following
an episode uses only successfully cached catalog ordering; watched fallback
rows cannot invent a next episode or season boundary. The same phone owns both
receivers' history. No media/stream URL/token is persisted in the Library.

## What failed / corrected

The installed physical pointer panel opened but could not navigate/select. New
source adds unlocked pointer/focused activation; tests exposed and corrected a
real direct-hover regression. Stale test copy/diagnostic expectations and the
TV fixture's result format were aligned; full reruns pass. Review corrected
metadata title sanitization, worker wakeup, catalog-only next proof and commit-time
SQLite failure handling. No remaining local failure is knowingly bypassed.

## Remaining questions

The new Library/catalog/resume and remote adapter are not physically accepted.
Last source is configured; wake from standby and visible browser restoration are
unverified. Native TV/DevView execution remains unresolved. Earlier untracked or
evicted history cannot be reconstructed. Offline artwork is URL metadata only.
No multi-phone/cloud synchronization or phone-off receiver hosting is promised.
